# 参考图生成个性化像素光标

## 面向使用者的承诺

用户提供参考图（附件、可访问的文件或宿主支持的图片资源）即可开始。具备下述制作能力时完成并交付能使用的光标包，而不只是设计建议、提示词、示意图或待填写模板。用户不需要认识图中角色，也不需要懂光标技术。

技能执行者负责读取图片、设计动作、调用绘图能力、处理素材、编写所需渲染代码、填写内部配置、校准热点、验证和打包。**不要把这些工作转交用户，不让用户运行制作命令、填写 manifest、拆图、定位坐标或逐项指定 17 个动作。**

## 跨 Agent 接入

本文件是普通 Markdown 工作流；不要求特定 Agent、模型、工具名称、调用前缀、Shell 或技能目录。支持技能的宿主可加载 `SKILL.md`；不支持技能的宿主可直接读取 [通用入口](START_HERE.md)，或读取同包的单文件 `PORTABLE_GUIDE.md`。`agents/openai.yaml` 仅是可忽略的特定宿主界面信息，不是运行依赖。

首次在新环境执行时，读 [能力适配](references/agent-adapters.md)，用实际暴露的工具映射看图、绘图、像素处理、二进制导出和文件交付。优先复用宿主现成能力；Python 辅助脚本是可选实现，不是唯一执行路径。缺少某工具名不等于缺少对应能力；只能输出文字的 Agent 无法凭技能自行获得绘图和二进制文件能力。

保持宿主的指令优先级与权限边界。跨 Agent 指执行环境可适配，默认生成的光标仍用于 Windows；不要将其宣称为可直接应用于所有操作系统。

## 收到图片后的默认行为

- 新用户直接走 [从参考图到成品](references/reference-to-pack.md)。查看附件或用户明确指定文件夹中的图片；本机没有旧项目也可以完成。
- 用户未补充要求时，默认 Windows 10/11、完整 17 状态、细腻而可辨的像素风、参考图主体与配色、适合长期使用的轻微循环动作、32/48/64px、动态 ANI 加静态 CUR。默认值由助手采用，不要做成问卷；已有用户要求优先。
- 自动选取图中最显著主体，提取外形、色调、服装/材质和辨识物。人物、动物、物件、标志或抽象主题都可以使用；不要把所有主题改成猫耳女孩。多图通常用于身份、风格或姿势参考，由助手辨别。
- 简短说明采用的方向，然后继续完成；无需在原型、动作表、提示词或每种状态之间反复等待确认。仅在图片无法访问/看清、多个主体同等突出且选择会改变主题、明确需求冲突，或实际能力/权限缺失时询问必要信息。
- 如果图片已经在上下文中，不让用户重复上传。只有用户明确要求“先给方案/先看样稿”时，才以该阶段为终点。

## 执行路径

1. **检查可用能力。** 按 [能力适配](references/agent-adapters.md) 选择当前环境支持的执行路径。已具备绘图能力就不询问密钥或模型；所需能力不依赖本地终端，也可以来自宿主提供的代码执行、插件或已授权服务。缺口用具体能力表述，不要求用户寻找一个本环境不存在的工具名。
2. **自动确定设计。** 读取 [设计与动作](references/design-and-motion.md)，从图片选定风格基准，在项目内部记录配色、轮廓、像素密度与 17 个状态的姿态。每种状态与功能有真实互动；保留角色身份，区分“参考图姿势”与“所有状态必须同一姿势”。
3. **生成并制作动作。** 使用原图与已稳定的代表姿态保持身份一致；按状态生成所需不同姿势，准备眨眼、呼吸或合适的局部动作。角色、道具、功能层分开处理；固定指尖/笔尖/文本中心等指示点。详细步骤、提示词和无需用户介入的修正方式见 [完整流程](references/reference-to-pack.md)。
4. **生成全部文件。** 助手自行生成最终尺寸 RGBA 帧与内部清单。有 Python/Pillow 和脚本访问能力时用 `scripts/cursor_io.py build`；其他环境用已提供的等效编码工具或依照格式规范在可执行运行时实现。制作接口见 [内部工具](references/tooling.md)。不要让用户填表。小范围修改保留已接受状态和其余文件。
5. **验证并交付。** 按 [Windows 文件与检查](references/windows-export.md) 检查二进制、热点、全部帧边界和加载，另做视觉与语义检查。可用时以 `scripts/package_cursors.py` 生成总览/动画/热点图/说明与成品 ZIP；否则在宿主环境完成同等步骤。通过该宿主真实的附件、下载链接或文件产物机制交付，默认整套不能漏项。

## 完成标准

- 默认交付 17 个 ANI、17 个 CUR、一张标注状态的总览、可查看的动画预览、使用说明和一个下载 ZIP；用户明确只要静态或单个状态时按其范围交付。
- 主题从用户图片得来；风格统一，实际大小能辨认；身体与道具不被意外裁切，手臂/支撑/握持自然；各状态有明确功能和独立设计。
- 任何动作不移动点击指示点；热点逐尺寸校准、逐帧固定。最近的不透明像素可能属于角色，不可作为语义校准的替代。
- 明暗背景、实际尺寸、循环首尾和中间帧均查看。加载成功不代表系统实际播放已测；如不在 Windows，说明原生加载未测。
- 修复检查发现的问题并重新验证受影响范围，不把已知缺陷和“用户自行调整”的任务一起交付。能力不足导致未完成时准确说明，不声称已完成整套。
- 生成光标不自动修改系统指针。说明如何应用即可，系统安装仅在用户要求时进行。

## 向使用者展示什么

最终直接展示预览、成品 ZIP、简短的使用方式和真实检查结论。内部设计表、提示词、参数和源码留在项目中，不要求使用者阅读。支持用户继续用“更清晰”“换色”“抱着笔”这样的自然语言修改。

分发本技能时一并提供 [给使用者的说明](使用说明.md) 和整个技能文件夹。只有继续蕾姆方案或需要历史设计示例时才读 [可选案例](references/rem-case.md)；案例不影响新用户默认设计。
