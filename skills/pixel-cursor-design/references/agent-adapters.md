# 按能力适配不同 Agent

## 入口和运行协议

本技能通过 Markdown 传递任务规则，不假设任何特定工具接口。先查看宿主当前提供的功能、工具说明与权限，再确定执行路径；不要发送本环境不存在的 `image_gen`、`exec` 或其他猜测调用。

| 宿主形态 | 如何加载 | 如何执行 |
|---|---|---|
| 支持技能文件夹 | 让宿主发现本包的 SKILL.md | 使用宿主实际提供的工具与路径 |
| 项目规则/工作区 Agent | 把整个包放入可读取的项目，用项目入口引用 SKILL.md | 遵循宿主规则文件机制；不自动覆盖现有规则 |
| 支持文件附件的聊天 Agent | 提供 PORTABLE_GUIDE.md 和参考图；能解压时也可提供整个 ZIP | 使用内置绘图、代码执行和附件导出 |
| 自定义工具调用框架 | 把技能正文/按需参考作为任务上下文，把真实工具按下表映射 | 由已有框架执行真实调用；能力名称不是新 API |
| 只有文字输出的模型 | 可读单文件指南并协助设计 | 缺乏绘图/执行/交付时不能独立完成成品，不能声称已生成 |

这些是接入方式，不是对每个具体产品/版本的实测认证。不要要求所有宿主使用相同安装目录、`$pixel-cursor-design` 前缀、YAML 界面文件或终端。

## 能力契约

以下名称用于内部规划，**不是需要原样调用的函数名**。

| 能力 | 必要输入与输出 | 可接受的实现 |
|---|---|---|
| 看图 | 接受参考图片，理解真实主体、风格和构图 | 模型原生视觉、查看图片工具或已有视觉服务 |
| 绘图/编辑 | 接受参考图和姿态约束，返回可提取的位图/图像资源 | 宿主内置绘图、已配置插件、本地图像模型或用户授权的图像服务 |
| 像素处理 | 实际读取像素/alpha、合成/缩放/减色、产生逐帧 RGBA 数据 | 代码解释器、Python/Pillow、JS 图像库、其他实际像素处理工具 |
| 编码与检查 | 能写入 CUR/ANI 二进制、重新解码核对、计算热点与帧时序 | 附带 Python 脚本、已有光标工具或依规范实现的其他运行时 |
| 文件交付 | 保存实际文件，提供用户可取得的 ZIP 和预览 | 宿主附件、artifact/download 工具、获授权文件系统 |
| Windows 原生检查（可选环境） | LoadImage/GetIconInfo 等实际加载与读回 | 当前 Windows 主机或已经授权的 Windows 执行服务 |

完整自动制作需要前五项，可以由多个已配置工具共同提供。没有命令行不等于不能生成文件：代码解释器和文件产物工具可能已足够。反之，仅能绘图但无法处理像素/编码的助手只能提供图片，不能谎称 PNG 已成为 ANI。

## 自动选择路线

1. **发现而非假设。** 查看工具目录、可执行运行时、工作区和文件交付机制。对于没有主动工具发现功能的宿主，使用它已声明的能力，不把某个工具名当必需条件。`scripts/probe_runtime.py` 只能检查它所在的 Python 环境，不能据其结果断言云端、浏览器或插件不可用。
2. **优先复用。** 使用已有、已授权且适合当前任务的绘图与执行能力。宿主自身的图像技能/说明存在时遵循它；不存在时不强制安装一个同名技能。不要为迁就附带脚本更换一个已可完成任务的运行时。
3. **选择编码路径。** 有 Python 3.10+、Pillow 9.1+ 和脚本访问时直接复用附带工具。没有这条路径但有等效工具时，按 [导出规范](windows-export.md) 和 [数据约定](tooling.md) 完成相同编码及检查。需要依赖时只在当前任务允许的环境中准备；不要更改用户全局设置来掩盖缺口。
4. **选择交付路径。** 本地 Agent 返回用户可访问的实际路径；云端 Agent 使用真实附件/下载机制，不把云端内部路径当成本机可打开的文件。图片预览通过当前宿主支持的方式展示，不硬编码某个平台的 URL 前缀。
5. **缺项才询问。** 能替代就继续；所有现有授权路径都无法满足某必需能力时，说明缺什么、目前已做到哪一步，以及一个具体可行的接入选择。不要静默切换到新的付费服务、代填凭据或要求用户提供技术设计参数。纯文字输出是能力限制，不是成功的降级成品。

宿主、模型和服务权限优先。本技能不授予新的外部上传/安装/收费权限，也不改变已有授权；用户已选用的图像服务按当前授权使用，不重复追问。密钥只通过宿主支持的本地/安全配置传递，不放进图片提示词、聊天、分发包或日志。

## 图片资源与文件路径

- 附件 ID、图像工具的资源 ID、URL、本地路径是不同对象。先依据实际接口取得可用的图像引用；不要把 `D:/...` 当作远程服务能访问的 URL，也不要凭空创造图片 ID。
- 远端返回图片时，用宿主允许的取回或文件产物方式保存像素；只显示预览但取不到源像素，仍不满足后续编码条件。不默认把私人参考图公开托管来换取一个 URL。
- 路径相对于技能实际位置、当前工作区或 manifest 所在目录解释。使用 Path/宿主路径 API 连接路径；Shell 调用根据实际环境正确引用，不混用 PowerShell、Bash 或 CMD 语法。
- 默认新建任务输出位置，参考图来源可为上传附件或用户选定文件夹。对于只有云端文件区的环境，也使用其可写空间，无需用户建立某个固定本机目录。

## 无 Python 的等效路线

不要求实现一个通用替代库；优先使用宿主现成工具。确实需要在 JS、其他语言或代码解释器中编码时，最低实现如下：

1. 得到每一尺寸、每一帧的 RGBA 像素数组，明确宽高、逐帧热点和时长；最终像素版采用一致的二值 alpha。
2. 按 [Windows 格式规范](windows-export.md) 写小端 CUR 目录和 DIB/BGRA+AND，再写 ANI 的 RIFF/ACON 块。处理 256 尺寸的 0 哨兵、掩码行对齐和 RIFF 奇数字节补齐。
3. 从生成字节重新解析，检查尺寸、热点、alpha/mask、帧顺序和首帧一致；不只比较自家编码函数的输入对象。用独立解析或原生加载提高证据强度。
4. 用可用的图像和压缩库生成明暗背景总览、逐状态动画、热点图、状态对照和 ZIP。逐项保留 [内部工具](tooling.md) 的交付要求。
5. 无 Windows 时标记原生加载未测；不是文件必然失败。只有代码文本、Base64 文本或示意图而没有可下载的实际文件，不算成品交付。

没有可用像素/编码库时，可以在具备执行能力的环境安装允许的依赖或使用已授权服务；不能只通过换扩展名补齐能力。

## 内部完成记录

每个任务记录实际采用的看图、绘图、处理、编码和交付方式，以及 `binary_checked`、`visual_reviewed`、`windows_native_checked`、`system_playback_checked` 的真实状态；未执行的检查标记未测。可记录为项目 JSON，但由助手填写，不给使用者加问卷。

跨 Agent 续作时一并保存实际参考资源、设计记录、源图、帧和现有产物。新 Agent 检查能否访问后再续作，不因日志写着“已完成”就推断文件仍存在。没有其他产品的实际运行证据时，只能声称提供兼容接入方式，不能声称“所有 Agent 实测通过”。
