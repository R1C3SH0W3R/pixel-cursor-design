pixel-cursor-design
给 AI Agent 一张参考图，由它完成像素风个性化动态光标的设计、制作、检查与打包。

这个 Skill 将角色设计、像素处理、动画制作和光标文件导出组织成可执行的工作流。使用者可以提供人物、宠物、物件、标志或风格参考，无需编写代码、准备动画帧、填写动作表或设置点击热点。

默认交付用于 Windows 10/11 的 17 种光标状态，包含动态 .ani、静态 .cur、预览和成品 ZIP。也支持修改已有方案中的某个状态，例如“文本选择让它趴着睡”“笔要抱在怀里”“角色更清晰一点”。

Skill 通过 Markdown 指令适配不同 Agent；附带脚本提供可复用的编码、检查与打包能力。它本身不包含图像模型、图像服务账号或调用额度，也不是双击运行的独立绘图软件。

快速使用
将技能交给 Agent，并提供一张或多张参考图，然后说：

请按 pixel-cursor-design 工作流，把这张图做成一整套像素风动态鼠标光标。其余由你设计，最后给我预览和成品包。

没有其他要求时，Agent 会采用参考图的主体与配色，安排各状态姿势和轻微循环动作，默认导出 32、48、64px 三种尺寸。用户明确提出的颜色、风格、动作、状态范围和尺寸要求优先。

这个 Skill 能做什么
从图片确定设计方向：提取主体轮廓、配色、服饰或材质、辨识特征，建立统一风格。
设计不同功能姿势：让角色与文本杠、笔、沙漏、指向手势等发生合理互动，避免同一张贴图机械替换角标。
制作像素动画：根据主体安排眨眼、呼吸、伸展、摆动或构件开合等动作，保持像素风格与身份一致。
处理可用性问题：检查实际尺寸可读性、完整显示、道具接触、遮挡关系和点击位置。
导出与检查文件：生成 CUR/ANI，检查帧、尺寸、透明度、热点和编码结构；Windows 环境下可执行原生加载检查。
交付成品：整理总览、逐状态动画、热点标注、使用说明、状态对照和 ZIP。

文件之间如何配合
SKILL.md 负责告诉 Agent“何时使用、按什么顺序执行、做到什么程度才算完成”。references/ 保存按需阅读的细节，避免每次任务都加载全部说明。

START_HERE.md 帮助不同宿主找到入口；PORTABLE_GUIDE.md 将主工作流和关键参考汇总为一个文档，适合无法读取整个文件夹的环境。单文件指南不内嵌 Python 源码，Agent 不能假定脚本已经存在。

scripts/ 负责确定性的文件操作。这些脚本不会自动从一张参考图绘制 17 个角色姿势：读图、角色绘画、局部动作与主题渲染仍由 Agent 调用实际绘图和图像处理能力完成，随后将最终帧交给编码器。

agents/openai.yaml 只提供特定宿主使用的界面信息，其他 Agent 可以忽略。rem-case.md 仅在需要该案例时阅读，不会把新主题强制改成蕾姆、猫耳或蓝色。

工作流程
参考图与自然语言要求
        ↓
确认当前 Agent 的看图、绘图、执行和文件交付能力
        ↓
提取主体与风格，确定统一色板和 17 个状态设计
        ↓
建立代表姿态，生成其他姿势与所需动作素材
        ↓
整理图层、统一像素处理、制作不同尺寸的动画帧
        ↓
确定每个尺寸的点击热点，并在所有帧中固定
        ↓
导出 CUR/ANI，独立解码检查并审阅预览
        ↓
修复发现的问题 → 重新验证受影响部分
        ↓
生成说明、状态对照、预览与成品 ZIP
1. 看图与确定方案
Agent 实际查看图片，识别主体、配色和辨识特征。主体明确时自主采用默认方案，不向使用者索要角色名、动作表和技术参数；只有图片不可访问、主体选择存在实质歧义或实际能力缺失时，才询问必要信息。

2. 设计状态与生成素材
先建立一个代表姿态，再以参考图和该姿态保持全套身份与画法一致。每种状态明确功能图形、角色动作、道具接触和布局。例如文本角色可以靠在杠旁，笔状态可以抱住笔，精确选择则需保留清楚的准星中心。

3. 制作像素和动画
整理透明背景、裁边、角色图层和道具层，从合适源图制作目标尺寸，统一色板与像素边缘。根据主体制作局部动作，检查循环首尾、动作最大范围和实际大小的可读性。不会以整张图片漂移代替所有角色动作。

4. 校准热点并导出
热点是系统实际执行点击的位置。Agent 将它对准箭尖、指尖、笔尖、文本杠中部或准星交点，并逐尺寸校准、逐帧保持固定。最终帧和内部清单由 Agent 生成，使用者不用填写坐标或 JSON。

有 Python/Pillow 和脚本访问能力时使用附带编码器；其他环境可采用现成光标工具，或依据格式规范实现等效编码与检查。

5. 检查与修正
检查分为三类：

检查层面	检查内容	边界
文件与像素	格式、尺寸、帧时序、透明掩码、固定热点、边距、静态与动画首帧一致	文件合法不代表人物结构自然或热点语义正确
视觉与设计	深浅背景、实际尺寸、动作衔接、角色完整性、握持关系、功能识别	由 Agent 实际查看，不由编码器自动判断
Windows 原生与交互	加载文件、读回热点与尺寸；需要时另测实际应用效果	原生加载成功不等于已验证系统动画播放
非 Windows 环境可完成制作与格式检查，但必须将 Windows 原生加载标记为未测。生成文件不会自动修改系统指针方案。

6. 打包与交付
默认检查 17 种状态是否齐全，并拒绝把完全相同的重复帧当作有效动画。通过后生成成品 ZIP；使用者得到实际可下载或可访问的文件，而非一段代码、虚构链接或只有预览的图片。

完整流程见 reference-to-pack.md。

成品包包含什么
默认完整输出示意如下；my-pixel-cursors 是示例包名：

my-pixel-cursors.zip
└── my-pixel-cursors/
    ├── files/
    │   ├── normal.ani             动态光标
    │   ├── normal.cur             静态备用光标
    │   └── …                      全部 17 状态，共 34 个光标文件
    ├── preview/
    │   ├── overview-light.png     浅色背景总览
    │   ├── overview-dark.png      深色背景总览
    │   ├── hotspots.png           点击热点标注图
    │   └── <state>.gif            各状态动画预览
    ├── 使用说明.md                Windows 应用步骤及状态对照
    ├── cursor-map.json            状态与文件的对应关系
    └── validation.json            实际完成的技术检查记录
最终 PNG 总览同时展示实际尺寸与整数倍放大视图。GIF 用于查看效果，真正的系统动画文件是 ANI。用户明确只要静态方案或局部状态时，交付范围相应缩小。

项目中的参考图、生成素材、提示词、逐帧文件和渲染代码可留作后续修改；默认成品 ZIP 不夹带这些中间文件、凭据或整个工作区。

应用时，在 Windows“鼠标属性 → 指针”中选择对应状态，点击“浏览”选取 ANI 文件并应用；需要静态样式时选择 CUR。具体步骤也会写入成品包的使用说明。

能力要求与兼容范围
完整自动制作需要 Agent 实际具备以下能力，可以由多个工具共同提供：

能力	用途
看图	理解参考主体、构图与风格
图像生成或编辑	制作新姿势、表情与所需素材
像素处理与执行	处理透明度、图层、尺寸、动画与热点
二进制编码与检查	产生并核对真实 CUR/ANI 文件
文件交付	提供预览和实际可取得的成品包
附带 Python 工具要求 Python 3.10+、Pillow 9.1+。具备其他等效执行能力的 Agent 可以采用其他路线；缺少某个工具名或终端，不代表缺少对应能力。

“跨 Agent”表示工作流和数据规范不绑定某个品牌，不代表所有产品及版本都已实测，也不表示纯文字模型能凭文档获得绘图或文件生成功能。Agent 的执行系统可以是 Windows、macOS、Linux 或云端，默认成品仍是 Windows 光标；其他目标系统需要单独适配。

更多接入和能力不足时的处理方式见 agent-adapters.md。

维护与扩展
修改工作流时优先编辑 SKILL.md 和相应 references/ 文件，再运行 scripts/make_portable_guide.py 更新单文件指南。不要只改 PORTABLE_GUIDE.md，否则下次生成会覆盖修改。

维护者使用 Python 路线时，可从技能根目录运行下面的命令；普通使用者无需执行：

python scripts/probe_runtime.py
python scripts/make_portable_guide.py
probe_runtime.py 只检查当前 Python 环境，不联网，也不能替 Agent 判断远程绘图或附件工具是否可用。运行命令时应使用实际环境中的 Python 解释器名称或路径。

新增主题应保存在独立制作项目中，复用本技能的设计与检查流程。新增编码或打包实现时，应保留现有的热点、透明度、动画和交付检查，而不只做到文件扩展名相同。工具输入格式及完整调用方法见 tooling.md。
